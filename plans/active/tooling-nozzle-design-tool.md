## 1. 目的

forge を粘性評価器とする超音速ノズル設計ツールを構築する。対象は 5 機種 (① 風洞ノズル軸対称 / ② 風洞ノズル矩形 / ③ スラスタベル / ④ デュアルベル / ⑤ SERN)。フロー空間設計変数 (中心線マッハ Bézier / 壁圧分布) + 帰還エンジンによる形状クロージャ + サロゲート支援多目的最適化 (随伴不採用) という基本構成はサーベイのパート B を採用する。完了時には「問題定義 → DOE → 帰還付き forge 評価 → パレート → 確認 CFD メニュー」が一気通貫で回り、最終的に問題定義そのものを AI とユーザの対話で組み立てられる状態を得る。

## 2. スコープ

- **やる**:

  - サロゲート支援 MOO ループ (co-kriging 多忠実度 + NSGA-II/III + EHVI infill; フレームワーク選定は §4.2)
  - 最適化後の**有望形状の数点抽出 + 特殊解析メニュー** (風洞: 複数入口条件の凝縮計算、スラスタ: 高度別計算 — §4.4)

- **やらない**:
  - 随伴法・forge への AD 導入 (サーベイ B4 の不採用判断を踏襲。再考トリガ: ⑤ 3D FFD 変数が 30–50 超でサロゲートが回らない場合に SU2 併用を検討)
  - ソルバ内 moving mesh / ALE (帰還は run 間の外側ループであり不要。ピントル過渡等の動的メッシュは対象外)
  - ML サロゲート (DeepONet 等) の採用 (成熟度未検証。infill 補助としても当面入れない)
  - 凝縮の最適化制約化 (§4.4 の通り「確認」に格下げ。サーベイ B4.5 の制約表から変更)

## 4. 設計方針

### 4.1 アーキテクチャと問題定義 YAML

レイヤ構成はサーベイ B1 (L1 設計変数 → L2 形状クロージャ → L3 forge 評価 → L4 目的/制約抽出 → L5 サロゲート MOO) を踏襲する。本計画での追加判断は 1 点:

**「問題定義 YAML」を Phase 0 から唯一の入力インターフェースにする。** 1 案件 = 1 YAML で、機種・設計変数 (選択・固定値化)・固定条件 (forge BC)・目的/制約 (B4.5 のメトリクス名から選択)・帰還モード (K/F, Euler/NS)・DOE/infill 予算・**確認 CFD メニュー** (§4.4) までを宣言的に記述する。理由: (i) run の再現性と記録 (case README との連携) がファイル 1 個で済む、(ii) 最終フェーズの AI 対話層 (§4.5) は「対話でこの YAML を組み立てて実行する薄い層」になり、ツール本体の改造なしに載る。

### 4.2 最適化フレームワーク選定 【決定 2026-08-03: 案 A (pymoo + SMT)。EHVI 自作が重ければ A' へ昇格】

要件: 多目的パレート、Kriging/co-kriging 多忠実度 (Euler 帰還=低 / NS 帰還=高)、**EHVI (または同等の多目的ベイズ) infill**、forge 評価の並列バッチ、全 Python。

| 案 | 構成 | 評価 |
| --- | --- | --- |
| **A (推奨)** | **pymoo + SMT を核**。サロゲート = SMT (`KRG`/`MFK` co-kriging)、探索 = pymoo NSGA-II/III (サロゲート上)、infill = EHVI を小規模自作 (2 目的は解析式 [Emmerich 系] で実装容易、3 目的以上は Monte-Carlo HVI)。評価パイプラインは素の Python 関数 (design vector → metrics dict) | 依存が軽く、**多忠実度 co-kriging (MFK) が第一級**なのが決定打。EHVI 自作分は ZDT/DTLZ ベンチで照合検証する負担を負う |
| **A'** | A のまま、EHVI acquisition だけ **BoTorch (qNEHVI)** を借用 | 自作検証負担が消え、並列バッチ提案・ノイズ耐性は既製最強。代償は torch 依存 (RTX 3060 で動作可)。SMT サロゲートと BoTorch GP の二重化をどう整理するかが設計点 |
| **B** | **BoTorch/Ax を BO エンジン一本に** | qNEHVI・多忠実度 GP とも既製だが、SMT の MFK ほど co-kriging が素直でなく、pymoo と役割重複。ツール全体が torch 色に染まる |
| **C** | **OpenMDAO を骨格に** | **標準 Driver は DOE/GA/DE/勾配系のみで EHVI・ベイズ MOO Driver が存在しない** → infill ループは結局外付け自作になる。OpenMDAO の本来の価値 (解析微分の連鎖・多分野連成 MDO) は随伴不採用・ブラックボック評価の本ツールでは使われない |

**推奨: A (必要になったら A' に昇格)。** OpenMDAO は不採用とするが、切り捨てにはしない — 評価パイプラインを「関数 1 個」に閉じて設計しておけば、将来冷却構造・システム連成など真の MDO 要件が入った時に OpenMDAO `ExplicitComponent` で包み直すのは薄い作業で済む (その時点で再評価する)。

### 4.3 形状更新と再メッシュ 【決定 2026-08-03: R1 (TFI 同一トポロジ再生成)。R2 は fallback 常備、R3 不採用】

前提の明確化: 帰還ループは **forge 実行の外側** (run と run の間) で壁を更新する。「計算中のリメッシュ」= ソルバ内 moving mesh は不要で、必要なのは**壁更新 → 新メッシュ → 前の場からの warm restart** を自動で回すパイプライン機能である。

| 案 | 方式 | 評価 |
| --- | --- | --- |
| **R1 (推奨)** | **同一トポロジ・パラメトリック再生成 + index 対応 restart**。Phase 0 のメッシュ生成器を「構造化 (i,j) トポロジ固定・壁スプラインから**代数生成 (transfinite 補間, Gmsh 非経由)**」で設計し、壁更新後も同ノード数・同接続で再生成。場は同 index でそのまま移植し、`wall_dist` は変換時に再計算 | 補間ノイズゼロ・完全に決定的 (サロゲートが要求する写像決定性に直結)・追加実装は生成器の設計方針だけ。ノズルは単連結流路なのでトポロジ固定が自然に成立する。**速度**: TFI は NumPy のみで 10 万ノード級でも数十 ms、`wall_dist` 再計算 (KD-tree) 込みでも 1 パスあたり ~1 s 未満 — forge 実行 (分オーダー) に対し無視できる。Gmsh を使うのは ⑤ SERN の 3D 非構造など TFI で張れない形状のみ |
| **R2** | **`interp_field.py` 最近傍 cross-mesh restart (既存ツール)** | トポロジ/解像度が変わる場面 (DOE 段間の解像度変更、機種切替) 用。運用実績あり。R1 の fallback として常備 |
| **R3** | **メッシュ変形 (RBF/ばね/弾性 warp)** — SU2/MACH-Aero 流 | 新規実装が要り、大変形で品質劣化・累積歪みの管理が必要。壁スプラインから毎回作り直せる本件では利点がない → **不採用** (⑤ SERN の 3D FFD 期にのみ再考) |

運用ゲート: 再生成のたび `check_mesh_quality.py` を通し (AR≤1000 / skew≤0.9)、FAIL は「評価失敗」として optimizer に返す (その設計点を実行不能扱い)。帰還 1 パスの壁変位は小さいので、R1 では restart 直後の過渡は数十 step で消える想定 — Phase 1 で実測して確認する。

### 4.4 凝縮・オフデザインは「確認 CFD メニュー」 (サーベイ B4.5 からの変更)

最適化ループ内では凝縮を**評価しない** (制約から削除)。設計点の最適化は乾き条件 (凝縮モデル OFF) で回す。$dM_c/dx$ の膨張率チェック (Daum–Gyarmathy) は CFD 前の**安価な事前フィルタとしてのみ**残す (明らかな不良候補の足切り。合否は確認メニューで判定)。

最適化完了後、パレートから**有望形状を数点抽出**し (抽出規準の既定: knee 点 + 各目的の端点 + ユーザ指名点。問題定義 YAML で指定)、各形状に対して YAML に書かれた**特殊解析メニュー (確認 CFD)** を自動実行する:

- **風洞 (①②)**: 複数の入口条件 (全圧・全温・組成/湿分のマトリクス) で凝縮 ON の計算を行い、**出口マッハ数・出口動圧の性能低下**を乾き設計値との差として表化する。評価器は検証済みの非平衡凝縮 ([condensation-nonequilibrium](../accepted/condensation-nonequilibrium.md))。
- **スラスタ (③④⑤)**: 有望形状のみ**指定高度 (背圧) のスイープ**で計算し、推力・剥離位置 (④は 2 作動点の遷移健全性) を評価する。
- 共通: 3D 最終確認・URANS 等の難解析もメニュー項目として同じ枠組みに載せる (サーベイ B8 の「最終確認」の実装形)。

### 4.5 AI 対話・自動化層 (最終フェーズ)

フロー全体が実績を持ってから着手する (Phase 5)。到達目標は「ヒアリングから報告書まで」(2026-08-03 ユーザ指示で拡張):

1. **ヒアリング**: ユーザ要望を対話で聞き取り、解析条件・設計変数・目的・制約・特殊解析メニューを問題定義 YAML (§4.1) に落とす
2. **試計算 → ユーザ承認**: 粗い試計算 (DOE 数点 + 帰還 1 パス程度) を回して結果を提示し、**承認ゲート**を通ってから本フローへ
3. **本フロー実行**: DOE → MOO → 有望形状抽出 → 特殊解析メニュー (§4.4) をジョブとして起動・監視・進捗報告
4. **成果物生成**: 選定形状の CAD (STEP) 作成 → 3D プリンタ入力 (肉厚付与ソリッド → STL) → 報告書 (パレート・選定根拠・特殊解析結果の表)

実装方針:

- **オーケストレーション = Microsoft Agent Framework (Python) を第一候補**とする。graph ベース workflow・human-in-the-loop 承認・checkpoint (長時間ジョブの中断再開)・MCP/関数ツール接続を備え、上記 1–4 の要件に直接対応する。ただし 2025-10 公開の新しいフレームワーク (Semantic Kernel + AutoGen の統合後継) なので、バージョン固定と**エージェント層を薄く保つ**こと (ツール本体は YAML と CLI しか見ない — §4.1 の設計がここで効く) で乗り換え可能性を担保する。
- **決定的な処理はエージェントに生成させない**: CAD/STL/報告書は通常の Python ツールとして実装し (CadQuery / pythonocc / FreeCAD headless — [case/37 で構築済みの環境](../../case/37.pintle_nozzle/) と `.venv-mesh` を流用)、エージェントは引数を組んで呼ぶだけ。LLM が直接書くのは要件ヒアリング・YAML 組み立て・報告書の説明文に限定する。
- 最適化ループ (時間オーダー) は会話内で待たず、ジョブ投入 + checkpoint/ポーリング監視で扱う。
- 印刷用ソリッドの注意: OCC 系の shell (肉厚付与) は複雑曲線で壊れやすいので、「壁曲線を法線オフセット → 回転体/ロフトで直接ソリッド化」する shell 非依存の専用生成にする (フランジ・分割等はテンプレートパラメータ化)。
- CAD/STL/報告書ツール自体はエージェント無しでも価値があるため、**Phase 4 と並行で前倒し実装してよい** (§5 の 5a)。

### 4.6 機種別の設計変数・目的関数 (詳細定義と実現性精査)

パラメータ化の理論的根拠 (Bézier・モード K/F・区分構成幾何) はサーベイ B2/A2.5(E)、メトリクスの数式定義 (測定面・重み・符号・無次元化) はサーベイ B4.5 を正とする。本節はそれを**実際に回す初期セット**に確定し、実現性を精査した結果を書く。

#### 共通 (a): 変数の 3 区分

問題定義 YAML では全パラメータを 3 区分で宣言する:

- **spec (仕様固定)**: 案件仕様 — 入口全圧/全温/組成、試験部径・設計マッハ (①②)、要求推力・燃焼室圧・背圧 (③④⑤)
- **derived (派生)**: spec から決まる量。ただし**スロート径 $r^*$ は、境界層排除厚さ δ\* と流量係数 $C_d$ が絡むため CFD を回す前には正確に決められない**。そこで次の「後決め」手順で閉じる (どちらも 1 変数の決定的な補正なので、最適化の探索次元 $d$ には数えない):
  - **$C_d$ (流量係数) とは**: 実際にスロートを通る質量流量 ÷ 1D 等エントロピー理論の質量流量。スロート近傍の境界層とソニックライン湾曲のぶん 1 より数 % 小さい (慣行値 ~0.98–0.995)。理論面積のまま作ると流量 (推力) が数 % 不足する。
  - **①② 風洞の後決め (出口径が強拘束の場合 — これが標準)**: 出口径 $D_e$ を守るとスロート径は**従属量**になるが、それで問題ない — 評価 1 回の内部で次の順に機械的に解消する。(1) $r^*=1$ の**無次元形状**で帰還 (§4.7(c) の逆設計ループ) を収束させ、粘性込みの「出口半径/スロート半径」比を得る → (2) 出口径が $D_e$ に一致する倍率で全体を相似スケーリング (**この倍率がそのままスロート半径** = 従属的に決まる) → (3) スケーリングで Reynolds 数が変わり δ\* の比率が僅かにずれるため、実寸で帰還を 1 パス回して壁を微修正する。壁が動くと出口径が再び僅かにずれるが二次の量であり、再スケール + 1 パスの 1–2 巡で収束する。
  - **過拘束の検出**: $D_e$ に加えて流量 (= スロート径) まで同時に強拘束すると面積比が決まってしまい、今度は設計マッハ $M_d$ が従属になる。($D_e$, $r^*$, $M_d$) のうち独立に指定できるのは 2 つ — 問題定義 YAML の読み込み時に整合チェックで弾く (3 つ指定されたらエラー、どれを従属にするか明示させる)。
  - **③④⑤ スラスタの後決め**: 守るべき仕様は「要求質量流量 (推力)」。$\dot m = C_d\,\rho^* a^* A^*$ から $r^*$ を仮決めし ($C_d$ は相関の見込み値)、**初回 CFD で実測した流量から $C_d$ を求め直して $r^*$ を 1 回補正**する ($C_d$ は $r^*$ にほとんど依存しないので 1–2 回で収束する)。
- **dv (設計変数)**: 最適化が振る。どれでも固定値化できる (B0 方針)

#### 共通 (b): 中心線マッハ Bézier の自由度勘定

CP の x 座標を等間隔固定 ($x(t)=L\,t$) にすると $M_c(x)$ は次数 $n$ の多項式となり、端点条件 1 個 = CP 1 個の拘束として消える。両端 C2 拘束 (①②: スロート側アンカー 3 + 出口一様 $M_d,\,M'=M''=0$ で 3) では**自由 CP 数 $k = n-5$**。出口一様条件が不要な推力系 (③) はスロート側拘束のみで $k = n-2$〜$n-3$。**実効 DV = 自由 CP の M 値 $k$ 個 + 軸長 $L$** とし、$k=2$–$4$ に抑える (次数 $n$ は $k$ から逆算)。単調性は「CP の M 値が単調」(単調カーブの十分条件 — B2) を bound + pymoo repair operator で強制する。壁圧 Bézier (⑤・④延長部) も同じ勘定 (端点 = 内部ノズル引き渡し圧・出口圧)。

→ **実現性: 高**。この勘定で全機種の総 DV 数 $d \le 7$ に収まり、サーベイ B4 の成立前提 (5–15 変数) の下限側で運用できる。

#### 共通 (c): 段階開放の規律

初回はパイプライン検証を優先し**最小 DV セット** (収縮 = Bell–Mehta 5 次固定、$R_u/R_d$ = 慣行値固定) で回す。$R_c$・収縮形状の DV 開放 (サーベイが新規性と位置づける $r_c$ パレート) は同一機種の **2 巡目以降**とし、一度に開くのは +2 変数までを目安にする (サロゲート再構築コストと、結果が変わったときの切り分けのため)。

### 4.7 壁の所有権と帰還エンジンの具体アルゴリズム

#### (a) 方式の明確化 — 本ツールは「目標分布による逆設計」が主。壁は直接 DV にしない

| 区間 | 壁を決めるもの | 最適化から見た扱い |
| --- | --- | --- |
| 収縮部 (入口配管 〜 $R_u$ 手前) | 直接幾何: Bell–Mehta 5 次 (収縮比・収縮長) + 円弧への曲率ブレンド | dv (初期は固定 — §4.6(c)) |
| スロート円弧 $R_u$–$R_d$–$\theta_a$ | 直接幾何: 円弧パラメータ | dv |
| 円弧終端 〜 出口 | **帰還エンジンの出力** ($M_c$ 目標 ①〜④ / $p_w$ 目標 ⑤・④延長部) | **dv ではない** (dv は $M_c$/$p_w$ Bézier の CP) |
| ⑤ 3D 段階のみ | FFD 直接変形 | dv (唯一の例外) |

旧ツールの「スロートを跨ぐ単一 5/7 次多項式壁」は**不採用** (A2.5(E) の診断: 曲率が区間内で振動し圧縮波源になる / 遷音速 starting line の曲率一定前提と不整合 / $R_u,R_d,\theta_a$ を直接制御できず Bartz 熱流束・$C_d$・ソニックラインの物理トレードと変数が対応しない)。ユーザ列挙の上流パラメータ (入口配管径・スロート径・円弧・スロート近傍の広がり角) は区分構成の区間パラメータに 1:1 対応する — 多項式を使うのは収縮壁 (Bell–Mehta 5 次) と接続ブレンドのみ。

#### (b) スロート近傍 → 中心線マッハ構成 (モード K の具体化)

「スロート近傍だけ計算 → きれいに繋がる $M_c$ を構成 → 壁角を調整」の 3 段を次で実装する:

1. **アンカーの定義と初期値 (解析)**: 「アンカー」= 目標 Bézier の始点条件 ($x_k$ での $M,M',M''$)。スロート円弧 ($R_d,\theta_a$) を決めた時点で、円弧終端から出る最終特性線が軸に当たる点 $x_k$ までの軸上マッハ分布は幾何の従属結果として決まってしまう (この円弧支配領域 = kernel)。目標 Bézier はその「続き」としてしか書けないので、$x_k$ とアンカー値を CFD なしで求めておく。手順: (i) スロート直近は遷音速で MOC が使えない → **Kliegel–Levine の解析級数** (円弧壁前提、入力は $r^*,R_d$ のみ) で少し下流の全超音速線 (starting line) 上の流れを式の代入で得る、(ii) そこから下流は超音速なので **MOC で前進計算** (壁はこの区間では既知の円弧) し、$x_k$ までの軸上 $M(x)$ を得る (ミリ秒オーダー)、(iii) $x_k$ の $M,M',M''$ に Bézier の先頭 CP を一致させる。**スロート近傍の別途 CFD は回さない** — forge は全域を解くので二重になる上、アンカーが CFD 結果に依存すると「同一 dv → 同一形状」の写像決定性が壊れサロゲートが劣化する (B2 モード K)。非粘性でよい理由: これは「目標を作る」計算であり、実流れは forge が解き、NS 帰還段でアンカーを実場値に更新するため粘性ずれは吸収される (下記 3)
2. **$M_c$ Bézier**: $x_k$ で上記微分値に接続 (①② C2 / ③⑤ C1 — B2)、下流は自由 CP (§4.6(b))
3. **壁角調整 = 帰還エンジン** (下記 (c)) と**アンカー更新 (実場)**。**更新が必要な理由**: 粘性の実場では kernel 区間の軸分布が解析予測からずれるが、円弧壁は凍結されているため**このずれは帰還では原理的に直せない** (円弧終端より下流の壁は $x_k$ より上流の軸に因果的に影響しない)。kernel 区間の分布は「目標」でなく幾何 dv の**結果**として受け入れ、NS 帰還段では目標 Bézier の始点を現在場の固定窓・固定次数 LSQ フィット値 ($M,M',M''$) に**張り替える** (B2 モード K (ii)) — これで継ぎ目の残差が構成的にゼロになり、直せない残差を追って継ぎ目直後の壁が暴れることを防ぐ。始点が動いた分は出口端条件 ($M_d$, $M'=M''=0$) を保持したまま自由 CP が吸収する。粘性 kernel の品質劣化 (小 $R_c$ のソニックライン非一様等) は実場から測る目的関数に現れ、最適化器が幾何 dv を動かして対処する (バイアスなし)。
   **更新のタイミングと安定性**: アンカー更新は**各帰還パスの冒頭に 1 回だけの離散操作** (1 パス = forge 収束計算 1 回 → アンカー更新 → 残差評価 → 壁更新 1 回) であり、CFD の反復中に目標を動かし続けるものではない。回数は infill 評価で 1–2 回、polish でも数回。不安定になりにくい構造的理由: (i) kernel の流れは凍結された上流幾何で決まり、超音速核に下流からの上流影響は存在しない (境界層亜音速部経由は弱い) ため、**アンカー値は初回 NS パスでほぼ確定し以後ほとんど動かない** — 「毎パス更新」の実態は初回 1 回の粘性補正 + 微小補正、(ii) アンカー更新は目標始点を現在場に合わせるだけの受動操作で、それ自体は壁を動かさない (追いかけ合いのゲインが小さい)、(iii) 残るドリフトは固定窓 LSQ 平滑化・$x_k$ 近傍重みランプ・壁更新緩和 $\omega$ が抑える。パス間でアンカーが振動するのは流れ側の病理 (スロート近傍剥離・非定常) であり、(c) のガードで評価失敗として弾く。防護は「アンカー更新 + $x_k$ 近傍の重みランプ + 円弧着地トレースのマスク ((c) ガード)」の 3 点セット

#### (c) NS 場特性線トレース帰還 — アルゴリズム仕様

入力: forge 場 ($M,\theta$, $\mu=\arcsin(1/M)$)、現在壁 $\theta_w(x)$ スプライン、目標 $M_{c,t}(x)$。1 パスは:

1. **軸分布抽出**: 固定相対 x 格子 (~200 点) へ $M_{achieved}$ を補間し、固定窓で平滑化
2. **残差**: $\Delta M(x_i)=M_t-M_a$。$|\Delta M|>$ tol の station のみ対象
3. **逆トレース**: 各軸点 $(x_i,0)$ から壁→軸波の族 ($dy/dx=\tan(\theta-\mu)$) を**凍結場の中で上流へ逆積分** (RK2・固定相対刻み) し、BL 端 (断面 95% $u_{max}$ — A2 定義) 到達点の真下の壁点 $x_w$ を得る
4. **PM 換算**: $\Delta\nu=\nu(M_t)-\nu(M_a)$、$\Delta\theta_w(x_w)=\omega\,\Delta\nu$ (緩和 $\omega=0.3$–$0.5$、正 = 開く方向)。軸対称の波増幅により PM は**近似 Jacobian に過ぎない**が、収束判定は実 CFD 場で行うため収束結果にバイアスは入らない (粗いと収束が遅いだけ — B3)
5. **基底射影**: $(x_w,\Delta\theta_w)$ 点群を $\theta_w$ スプライン係数増分へ Tikhonov 正則化付き最小二乗で射影。$x_k$ (アンカー) 近傍と出口近傍は重みランプでゼロ化。1 パスの $|\Delta\theta_w|$ はクリップ (例 0.5°)
6. **壁再構築**: $y(x)=y_a+\int\tan\theta_w\,dx$ (円弧終端の位置・角・曲率をアンカー) — 位置・勾配連続が構成的に保証される
7. **R1 再メッシュ → warm restart → 次パス** (§4.3)

運用規律 (B3 の表を実装値化):

- **収束**: 最終 polish は $\|\Delta M\|_\infty \le 0.5\%\,M_d$。infill 評価は**固定 1–2 パス** (打ち切り判定の段差が写像に不連続を作るのを避ける)
- **ガード**: トレースが $M<1.05$ 領域・剥離域 ($\tau_w<0$) に入った station、および**凍結された円弧区間 ($x_w < P_a$) に着地した station** はマスク (そこは帰還で直せないため — (b)3)。マスク率 >20% でその設計点は評価失敗として optimizer に返す
- **決定性**: station 格子・積分刻み・平滑化窓・BL 端定義・$\omega$・正則化 $\lambda$ を全て問題定義 YAML に固定値で持つ
- **Euler 帰還版**: 同一アルゴリズムを Euler 場 (粗格子) で回し、物理壁 = 非粘性壁 + $\delta^*(x)$ 法線オフセット (決定的積分法)。BL 端検出は不要 (壁マッハを直用)
- **壁圧帰還版 (⑤・④延長部)**: $\Delta p_w$ が局所壁角に直結するためトレース不要の局所帰還 (ステップ 3 を省略し、4 の換算を $p$–$\theta$ 関係に置換)

#### 計算予算の見積り (実現性の裏付け)

$d\le6$ なら LHS DOE $\approx10d=60$ 点 + infill 30–50 点。1 評価 = Euler 帰還 (分オーダー) または NS 帰還 1–2 pass (axisym SST・warm restart で 10–30 分/RTX 3060 想定) → **1 機種 1 巡 ≈ 数日**で回る規模。④ の 2 作動点・⑤ 段階 2 はこの 2–10 倍で、[tooling-cloud-gpu-env](tooling-cloud-gpu-env.md) のバッチ並列が効く場面。**Phase 2 で 1 評価の実測時間を取り、本見積りと DOE/infill 予算の既定値を更新する。**

## 6. 検証

- **Phase 0**: 生成器の決定性 (同一 YAML → bit 同一メッシュ)、品質ゲート、既存 case ([case/23.axi_nozzle], [case/13.nozzle_H]) の手作りメッシュと同等品質の再現。
- **Phase 1**: 帰還収束性 — 既知目標分布 (Sivells/CONTUR 系コンタの中心線分布) を与えて元コンタを回復できるか。R1 restart の過渡長の実測。
- **Phase 2 (最重要マイルストーン)**: **Rao TOC/TOP ベルとの照合** — パレート前線が Rao 点と整合し、かつ Rao を不当に支配しない (支配するなら評価系のバグをまず疑う)。[case/29] の Rao vs 円錐資産を照合解に使う。

- **全フェーズ共通**: AGENTS ルールのツール化 — 各評価 run で `check_mesh_quality` / `check_convergence` / `check_quasisteady` の VERDICT を自動記録し、PASS 以外の点はサロゲートに入れない (失敗扱い)。run は `case/` 配下の専用 case ディレクトリに置き README の run 一覧表を維持する。
